# Telegram Mini App: 12 Week Year + Essentialism

Полноценное веб-приложение внутри Telegram (Telegram Mini App / Web App) для
женского комьюнити (14 участниц, будет расти). Ведёт участниц по системе
"12 Week Year", отфильтрованной через принципы Essentialism (Explore,
Eliminate, Execute), с полноценным 12-недельным тактическим планом,
еженедельными чек-инами, скорингом и командами поддержки.

## Архитектура

- **Бот (aiogram 3.x)** — только точка входа: `/start` открывает кнопку
  "Открыть приложение" (Telegram WebApp button), дальше вся логика внутри
  Mini App. Бот также используется для рассылки уведомлений о чек-инах
  и отправки автобэкапа админу.
- **Бэкенд (FastAPI)** — REST API, обслуживает и данные Mini App, и статику
  фронтенда. Работает в одном процессе с ботом (или соседним процессом в
  том же контейнере).
- **Авторизация в Mini App**: проверка `initData` от Telegram WebApp SDK
  (валидация подписи через хэш с использованием токена бота) — так бэкенд
  надёжно узнаёт, какой именно пользователь Telegram открыл приложение,
  без паролей и логинов.
- **Фронтенд**: HTML/CSS/JS (React допустим, если проще для Claude Code
  генерировать компонентами) + `Telegram.WebApp` SDK для темы оформления,
  кнопок Telegram (MainButton/BackButton) и haptic-фидбека.
- **База данных**: SQLite через SQLAlchemy — общая для бота и FastAPI.
- **Хостинг**: Fly.io (бесплатный тариф, до 3 приложений, 3 ГБ persistent
  volume). Mini App обязательно требует HTTPS — Fly.io даёт это из коробки.
  SQLite-файл должен лежать на volume, а не в обычной файловой системе
  контейнера, иначе данные пропадут при перезапуске/редеплое.
- **Автобэкап базы данных**: раз в сутки по расписанию (APScheduler) бот
  отправляет файл SQLite как документ в личку админу в Telegram —
  резервная копия независимо от хостинга, на случай сбоя или ошибки при
  деплое.

## Экраны Mini App (онбординг)

1. **Приветствие** — короткое объяснение концепции: что такое 12 Week Year
   и зачем в нём фильтр Essentialism
2. **Колесо баланса** — интерактивная визуализация (radar/spider chart или
   набор ползунков), участница оценивает 6–8 сфер жизни от 1 до 10: карьера,
   здоровье, отношения, финансы, саморазвитие, отдых (и ещё 1–2 по желанию).
   Сразу видно, где просадки — это подсказка для следующего шага
3. **Explore** — свободный список: добавление пунктов "что для тебя важно
   прямо сейчас" без ограничений по количеству (простой список с
   добавлением/удалением)
4. **Eliminate** — из списка выше нужно выбрать ровно 3 приоритета на
   ближайшие 12 недель (чекбоксы, после выбора 3 остальные блокируются —
   жёсткий фильтр, не 4 и не 5)
5. **Essential intent** — по каждому из 3 приоритетов текстовое поле
   "почему это для тебя важно" (связь с более широким видением, не просто
   галочка)
6. **Тактики и 12-недельный план** — по каждому приоритету добавляется
   **несколько тактик** (обычно 3–8, не 1–2), и у каждой тактики
   указывается, на какие недели цикла (1–12) она приходится:
   - повторяющаяся (например "каждую неделю", т.е. недели 1–12)
   - конкретные недели (мультиселект, например недели 2, 6, 12 — контрольные
     точки)
   - разовая в одну конкретную неделю
   Визуально — что-то вроде таблицы/таймлайна 12 колонок (недели) x строки
   (тактики), где отмечено, в какую неделю какая тактика активна
7. **Итоговый экран** — сводка: 3 приоритета, essential intent по каждому,
   полный тактический план на 12 недель. Подтверждение → участница
   помечается "готова" и автоматически распределяется в команду (см. ниже)

## Еженедельный цикл (экраны)

- **Чек-ин**: экран показывает список тактик, которые "выпадают" на текущую
  неделю цикла (по номеру недели, вычисленному от даты старта участницы) —
  собираются из тактик всех 3 приоритетов. Отметка выполнено / не выполнено
  по каждой (переключатели/чекбоксы), кнопка "Сохранить"
- **Scorecard**: `% = (выполненные тактики / запланированные тактики) × 100`
  за неделю. Показать графиком/историей по неделям:
  - 85%+ — отлично (зелёный)
  - 70–84% — хорошо, но есть что подтянуть (жёлтый)
  - ниже 70% — сбой в исполнении, стоит разобраться (красный)
- **Отчёт настраиваемый**: у каждого пользователя флаг `send_report`
  (в чат команды / лично админу / никому) — переключатель прямо в
  настройках профиля внутри Mini App
- **Команда**: экран с сокомандницами (максимум 3 человека), у каждой —
  только % выполнения за неделю (прогресс-бар), без деталей целей/тактик
  (приватность)

## Команды (аналог WAM — Weekly Accountability Meeting)

- Максимум 3 человека в команде
- Заполнение непрерывное, без ожидания: как только участница становится
  "готова" (прошла экраны 1–7 онбординга), бэкенд ищет существующую команду
  с < 3 участниками
  - есть свободное место → добавляет туда
  - нет (все заполнены или команд ещё нет) → создаёт новую команду и
    добавляет туда первой
- Админ может вручную переместить участницу между командами (через
  админ-экран в Mini App или отдельную команду боту)

## Essentialism — ключевые механики (должны быть видны в интерфейсе)

- Explore идёт **до** Eliminate (сначала расширяем список, потом режем до 3)
- Essential intent обязателен для каждого приоритета — без "зачем" легко
  бросить приоритет на 5-й неделе
- Подсказка-фильтр при добавлении новой тактики в середине цикла: "если это
  не однозначное да — это нет"
- Необязательная подсказка при планировании недели — оставлять буфер на
  непредвиденное, не забивать неделю на 100%

## Структура базы данных

`users`, `wheel_of_balance`, `explore_list`, `priorities` (3 на юзера),
`essential_intent`, `tactics` (несколько на приоритет, с полем недель:
JSON-список номеров недель 1–12 или флаг "recurring"), `checkins`
(привязаны к конкретной тактике + номеру недели), `teams`, `team_members`

## С чего начать

1. Структура проекта: разделить на `bot/` (aiogram) и `webapp/` (FastAPI +
   статика фронтенда), общий `models.py` для SQLite
2. `requirements.txt`
3. `models.py` — все таблицы (путь к файлу базы через переменную окружения,
   чтобы легко переключить на путь volume при деплое)
4. Настройка бота: токен через `.env`, хендлер `/start` с кнопкой
   "Открыть приложение" (WebApp button)
5. FastAPI: эндпоинт для валидации `initData` и получения/создания
   пользователя
6. Первый экран фронтенда — приветствие + колесо баланса (можно на чистом
   HTML/CSS/JS для скорости, без сборки)
7. Дальше наращиваем экран за экраном, шаг за шагом — не всё сразу
8. Когда основные экраны готовы и протестированы локально (можно
   тестировать через ngrok/localtunnel для HTTPS-туннеля к локальному
   серверу, Telegram требует HTTPS даже для теста) — `Dockerfile` и
   `fly.toml` для деплоя на Fly.io с persistent volume
9. Планировщик автобэкапа базы (APScheduler, раз в сутки, отправка файла
   админу в личку через бота)

Дальше наращиваем пошагово, шаг за шагом — не всё сразу.
